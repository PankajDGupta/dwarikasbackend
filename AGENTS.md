
## Application Building Context

Read the following files in order before implementing or making any architectural decision:

1. `context/project-overview.md` — product definition, goals, features, and scope
2. `context/architecture.md` — system structure, boundaries, storage model, and invariants
3. `context/ai-workflow-rules.md` — development workflow, scoping rules, and delivery approach
4. `context/progress-tracker.md` — current phase, completed work, open questions, and next steps
5. `context/system_design.md` — system design and architecture
6. `context/backend_capabilities.md` — backend capabilities that frontend developers can refer


Update `context/progress-tracker.md` after each meaningful implementation change.
update `context/backend_capabilities.md` after each meaningful feature addition.

If implementation changes the architecture, scope, or standards documented in the context files, update the relevant file before continuing.
